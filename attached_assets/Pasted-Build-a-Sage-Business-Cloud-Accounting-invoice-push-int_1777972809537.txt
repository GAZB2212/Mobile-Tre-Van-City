Build a Sage Business Cloud Accounting invoice push integration for our existing Autotrade Portal website.

Context:
The website already has backend configurators where customers/specs are created for vehicle builds and products. We do NOT need to rebuild the configurators. We need to take an existing configured quote/order/spec from the backend and push it into Sage as a sales invoice.

Sage app details:
- We already have a Sage Accounting API app created.
- Callback URL is:
  https://autotradeportal.com/api/sage/callback
- Use environment variables:
  SAGE_CLIENT_ID
  SAGE_CLIENT_SECRET
  SAGE_REDIRECT_URI=https://autotradeportal.com/api/sage/callback

Main requirements:

1. Add Sage connection flow
- Add backend route: GET /api/sage/connect
- This redirects the admin user to Sage OAuth login.
- Use Sage OAuth for Sage Business Cloud Accounting.
- Add callback route: GET /api/sage/callback
- Exchange the returned code for access_token and refresh_token.
- Store the tokens securely in the database.
- Do not expose Client Secret or tokens in frontend code.
- Add token refresh logic so expired access tokens are automatically refreshed.

2. Add Sage settings page in admin
Create an admin-only page called “Sage Integration” with:
- Connection status: Connected / Not connected
- Button: Connect to Sage
- Button: Disconnect Sage
- Display last successful sync date
- Display token expiry/status
- Test connection button
- Pull and store Sage ledger accounts
- Pull and store Sage tax rates

3. Data formats needed
For each configurator/order/spec, create a normalised invoice payload before sending to Sage.

Expected internal invoice format:
{
  customer: {
    name: string,
    email: string,
    phone: string,
    address_line_1: string,
    address_line_2: string,
    city: string,
    postcode: string,
    country: "GB"
  },
  invoice: {
    invoice_date: "YYYY-MM-DD",
    due_date: "YYYY-MM-DD",
    reference: string,
    notes: string,
    status: "draft" or "unpaid"
  },
  line_items: [
    {
      description: string,
      quantity: number,
      unit_price_ex_vat: number,
      vat_rate: number,
      sage_ledger_account_id: string,
      sage_tax_rate_id: string,
      source_type: "van" | "conversion" | "equipment" | "extra" | "labour" | "delivery" | "discount"
    }
  ],
  totals: {
    subtotal_ex_vat: number,
    vat_total: number,
    total_inc_vat: number
  }
}

4. Sage invoice mapping
Map our internal format to Sage sales invoice format.
Use Sage Accounting API v3.1.
Before sending an invoice:
- Check if the customer/contact already exists in Sage by email or name.
- If not found, create a Sage contact.
- Use the Sage contact ID in the invoice.
- Use selected Sage ledger account IDs and tax rate IDs on each invoice line.
- Store the returned Sage invoice ID against the original configurator/order/spec record.

5. Preview before sending
Add a “Push to Sage” button on each configurator/order/spec in the admin backend.

When clicked:
- Do NOT send immediately.
- First open a preview modal/page called “Sage Invoice Preview”.

The preview must show:
- Customer details
- Invoice date
- Due date
- Invoice reference
- Each invoice line
- Quantity
- Unit price excluding VAT
- VAT rate
- VAT amount
- Line total excluding VAT
- Line total including VAT
- Selected Sage ledger account
- Selected Sage tax rate
- Subtotal ex VAT
- VAT total
- Total inc VAT

Add validation warnings before sending:
- Missing customer name
- Missing customer email
- Missing Sage ledger account
- Missing Sage tax rate
- Negative or zero invoice total
- VAT mismatch
- Already pushed to Sage
- Sage not connected

The preview must have:
- Button: Cancel
- Button: Save as Draft in Sage
- Button: Create Final Invoice in Sage

6. Draft-first safety
Default behaviour should be safest:
- “Save as Draft in Sage” should be the recommended/default action.
- “Create Final Invoice in Sage” should require confirmation.
- If an invoice has already been pushed, do not duplicate it unless admin confirms “Create duplicate invoice”.

7. Audit log
Create an audit log for every Sage action:
- user_id
- order/spec/configurator ID
- action type: preview_created, draft_invoice_created, final_invoice_created, failed_sync, token_refreshed
- Sage invoice ID if available
- timestamp
- request payload snapshot
- response/error message

8. Error handling
Show clean admin-friendly error messages:
- Sage not connected
- Token expired and refresh failed
- Contact creation failed
- Ledger account missing
- Tax rate missing
- Invoice validation failed
- Sage API returned error

Do not crash the app. Log detailed errors server-side.

9. Security
- Keep Sage credentials only in backend environment variables.
- Never send Client Secret to frontend.
- Protect all Sage routes behind admin authentication.
- Tokens must be stored securely.
- Add CSRF/state protection to OAuth flow.
- Validate that the callback state matches the original request.

Use the existing admin UI styling.
Add:

- Status badges:
  Connected
